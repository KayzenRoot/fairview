# FV-ADR-017 | Independent browser operator boundary, scoped read models and safe controls

**Status: PROPOSED_NOT_ADOPTED.** FV-DISC-001 Round 9. No browser UI, external authentication service, API endpoint, trading control or SaaS deployment has been implemented.

## Decision proposal
Maintain the existing `web` module as a strictly authenticated **operator client/BFF**, never a direct trading engine, browser-to-broker proxy or financial source of truth. Evaluate Next.js App Router/React with a properly reviewed auth library, server-side resource-level Data Access Layer, minimal redacted and provenance-linked `OperatorReadModelV0` DTOs, tenant/access-partitioned caching and a candidate one-way SSE stream (`OperatorStreamEventV0`). Every server route/action/stream must reauthorize the trusted session, role, tenant, resource and data licence before sending content. `OperatorSessionV0` uses session expiry/revocation and step-up for separately approved future controls. A client-side disabled button, stale SSR cache or guessed opaque account ID is never an authorization boundary.

Views proposed: Overview, Markets, Strategies, Portfolio, Risk, Replay, Incidents, Advisory and Settings. Data freshness and mode (`SYNTHETIC | HISTORICAL | DEMO | REAL_OBSERVED | UNKNOWN`) are displayed explicitly. Server-issued kill status, actual ledger/venue receipts and reconciled PortfolioRiskView versions outrank charts/optimistic client state. Stream gap, network loss, role switch, data licence revocation or browser restart quarantines affected caches and triggers **read-only reauthorization and fresh snapshot**; no automatic replay of an intent.

Propose future `OperatorCommandRequestV0`/`OperatorCommandReceiptV0` for narrowly scoped restrictive pause, kill request and read-only reconciliation **only under a separate admitted control-plane WO**. A human click merely requests action; independent signed backend state/receipt is required to claim it was applied. No risk-increasing action, kill reset, direct broker/order endpoint, secret entry or signing is approved by this ADR. Future safety officers, MFA and dual-control must be independently reviewed against operator/venue authorization and explicit financial release gates.

## Source and candidate technology
Next.js official guidance favors an auth library plus DAL and server-side per-action/per-route/resource checks: https://nextjs.org/docs/app/guides/authentication . TanStack Query documents asynchronous cache/synchronization; it is optional UI state management, not financial truth: https://tanstack.com/query/latest/docs/framework/react/overview . The R8 OpenTelemetry/Prometheus/Grafana observability plan is a redacted non-authoritative read source, never a risk/fill oracle. OPA fine-grained authorization is optional later if policy scale warrants it, not a second Risk Kernel: https://www.openpolicyagent.org/docs/http-api-authorization .

## Reject shortcuts and required future proof
Reject browser credentials in localStorage, direct privileged broker/RPC calls, tenant-scoped data assembled in globally shared caches, automatic command retries on SSE reconnect, green risk dashboards from stale snapshots, and treating HTTP 200/UI acknowledgment as an authoritative kill/position receipt. First admitted source WO must pass SESSION_EXPIRED_STREAM, CROSS_TENANT_IDOR, ROLE_SPOOFING, CSRF_MUTATION, CROSS_TENANT_CACHE, STREAM_SEQUENCE_GAP, RECONNECT_DUPLICATE_ACTION, CLIENT_FAKED_KILL_ACK, KILL_RESET_FROM_UI, STALE_PORTFOLIO_GREEN and WEB_BROWSER_RESTART negative synthetic harnesses. No implementation until FV-BOOT-001 independently evidenced FULL and separately signed security scope.
