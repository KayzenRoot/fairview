# FV-ADR-018 | No-tools bounded AI advisory with untrusted-evidence isolation

**Status: PROPOSED_NOT_ADOPTED.** FV-DISC-001 Round 9. No inference model, cloud account, external request, runtime embedding or model tool is approved or installed.

## Decision proposal
Keep existing `ai` as a strictly **read-only, non-authoritative advisory/research component** separated from the live Risk Kernel, venue connectors, wallets, ledger and operational command endpoints. Its future `AdvisoryRequestV0` may ask for `EXPLAIN | ANOMALY_TRIAGE | BENCHMARK_COMPARE | RESEARCH_TUNING_PROPOSAL` on only authorized tenant evidence. A server-prepared bounded `EvidencePackV0` holds finite size-limited, provenance-linked and licence-checked **sanitized** facts; vendor docs, news, market metadata and logs are marked UNTRUSTED DATA. Its output `AdvisoryFindingV0` must distinguish observed facts, hypothesis, unverified assumptions and missing data, citing approved source IDs. A proposed `TuningProposalV0` remains `RESEARCH_ONLY` until separately validated through the R4 deterministic replay laboratory and independent human Risk/Policy approvals. `AdvisoryAuditV0` stores redacted private hashes of model/prompt version, evidence scope, output and refusal.

No AI-bound tool may place/cancel orders, call an authenticated exchange or RPC, sign, transfer, withdraw, modify live limits, reset a kill switch, activate strategy configuration, fetch other tenant/source data, retrieve unrelated private engineering files or commit a production change. Advisory has no access to unapproved development-only context files or production trading tools. A missing or failing model makes advisory UNAVAILABLE and changes no independent financial state. A cloud or local model is a **future** separately reviewed deployment decision conditioned on data-use, privacy, availability and licence proofs; no model or inference vendor is chosen here.

## Threat model and official guidance
OWASP LLM application guidance identifies indirect prompt injection and excessive agency among core risks; system prompts alone cannot enforce capability isolation: https://owasp.org/www-project-top-10-for-large-language-model-applications/ . Handle external documents, web pages, logs, quote metadata and model outputs as untrusted; no role promotion from forged `system` messages, no broker endpoints in generated code paths and no self-approval. Independently validate scope/citations/output schema, reduce tool permissions to zero for live financial mutation, apply bounded context/time/usage budgets and never export unlicensed raw tick, account/order detail, PII, secrets or wallet material to an unapproved model.

## Reject shortcuts and required future proof
Reject giving an LLM a generic function dispatcher with opaque HTTP/SQL/shell access, translating natural language into an order or kill command, using generated PnL as a financial ledger or allowing a cloud model to receive every document by default. Future separate AI source WO: invented synthetic facts only, AI_MARKET_PROMPT_INJECTION, AI_FORGED_SYSTEM_MESSAGE, AI_TOOL_CALL_LAUNDERING, AI_CROSS_TENANT_RAG, AI_UNLICENSED_DATA_USE, AI_FABRICATED_FILL, AI_SELF_APPROVED_TUNING and MODEL_SERVICE_OUTAGE must fail closed in isolated harness. Independently approved FV-FOUNDATION-002 FULL, privacy rights, model provider retention guarantees and actual authz tests are prerequisites.

**Accepted foundation D-009:** pure synthetic module admission depends on current Git-only source governance, exact-head CI and real module-owned tests. Financially privileged operation additionally requires independent security and actual provider/data-use rights. No separate background host acceptance is required.
