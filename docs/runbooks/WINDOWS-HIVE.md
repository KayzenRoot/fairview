# Fairview Windows bootstrap and local HIVE v1.0.3
This runbook is operator-executed only, not evidence of installation. Do not execute on a Windows machine with unbacked HIVE data; script refuses unexpected pins/existing sources. No secrets in Git or CI.

1. Ensure Windows PowerShell 7 or Windows PowerShell 5.1, Git, Node.js 22+, npm, Python 3.12, Docker Desktop Linux containers and permission for Docker to access drive D:. Clone `KayzenRoot/fairview` to `D:\Projects\Fairview` (after merging approved bootstrap). If source exists, avoid destructive reclone.
2. Execute `powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\local\setup-windows.ps1 -Mode Doctor`, then `-Mode Install` from that checkout. Script initializes pinned GEF source at v1.0.0, validates npm workspace, clones pinned HIVE v1.0.3 to D:\Tools\HIVE if absent, keeps HIVE data at D:\HIVE, project root D:\Projects and starts HIVE via the upstream idempotent installer.
3. Independent smoke: `powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\local\check-hive.ps1`. It checks health, actual Fairview registry state READY, on-demand Git indexing, corpus sync and lexical retrieval. On first indexing allow bounded discovery; if not READY investigate Docker mount and avoid inventing success.
4. To require semantic search, configure a real trusted OpenAI-compatible embedding endpoint and matching HIVE_EMBEDDING_* settings in LOCAL HIVE .env; then run `check-hive.ps1 -RequireSemantic`. If absent, the command reports BLOCKED and does not claim all search capabilities. Do not put endpoint secrets or provider keys in repo. Hybrid lexical fallback is distinguishable from semantic CURRENT.
5. HIVE MCP read-only surface is separate from REST startup; verify actual handshake in its execution host before claiming tool access. Never invent project/task UUID.
6. Capture logs without credentials, exact Git pins, health result, project READY state, index/corpus receipts, search results and failure exit code in an Evidence Bundle. Operator machine success is independent of GitHub CI.
Uninstall/upgrade is intentionally not automated; no volume deletion, migration or repository history rewrite under this Work Order.
