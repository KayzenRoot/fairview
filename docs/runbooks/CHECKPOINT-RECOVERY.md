Never require `CHECKPOINT.json.last_audited_head_sha` to equal the hash of the commit containing that file. This is an impossible self-reference under Git's content-addressed commit model. The field is historic audit provenance, not a mutable alias for current HEAD.
Canonical local admission proof is **external**: compare local clean HEAD, refreshed `origin/main`, GitHub API `main`, the exact head's completed successful main push CI containing the FOUR required jobs, and a post-CI owner-authored `FAIRVIEW_CHECKPOINT_RECEIPT_V1` issue #1 comment matching the exact SHA and run ID. Use `scripts/local/verify-checkpoint.ps1`.
External receipt syntax: `FAIRVIEW_CHECKPOINT_RECEIPT_V1 sha=<exact40> ci=<workflowRunId> scope=LOCAL_DEV_PRECHECK audit=OWNER_SELF_AUDIT`. Post this only **after** the main CI completes; never paste product secrets into issue comments. The verifier rejects missing, stale, untrusted and divergent receipts. Owner-self-audit is never represented as independent.
If local HEAD differs, do not force reset or drop commits. Inspect and report `git log --graph --decorate --all -n 15`, `git merge-base HEAD origin/main` and redacted `git status --short`; if differences are approved and local-only, coordinate a reviewed branch/PR and obtain fresh exact-head receipt after integration.
