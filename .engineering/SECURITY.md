# Fairview security | HIGH_ASSURANCE
Do not commit API keys, wallet seeds/private keys, passwords, PII, customer account data, .env or live trade logs. Treat public repository as non-confidential. Prefer non-custodial or least-privilege connector identities and offline-controlled signing for DeFi.
Every new live trading route requires approved threat model, contract/legal permission, idempotency, reconciliation, replay tests, bounded proof obligations, independent review for high-assurance safety, tested kill switch and rollback or roll-forward.
Use environment-specific secrets provided at runtime, never as PDF payloads, CI artifact contents or prompt context. CI does not have live-trading keys. GitHub status gates cannot substitute product runtime safety.
Current bootstrap gate: no trade/wallet or secret-bearing code. Local HIVE data root must be separate from read-only source mount. Installation scripts preserve .env and existing storage; do not delete Docker volumes.
Security findings HIGH/CRITICAL prevent promotion and live activation.

## Public-development repository policy (owner accepted D-008)
- PUBLIC source repository and unprivileged public CI/CD are permitted **only during development**. A verified PRIVATE repository plus production safety approval are separate mandatory pre-production gates. Making a repository private does not erase already exposed public Git objects or forks; treat anything committed during public development as permanently public.
- Never add any Fairview `.env` or `.env.*`, including `.env.example`; no real/placeholder credentials in tracked config, tests, commits, GitHub issue/PR text, screenshots, PDFs, or uploaded CI artifacts. Non-secret configuration contracts must be schema/docs, not environment files.
- Never put live broker/exchange API tokens, signing keys, seed phrases, customer data or real trade logs in Git, GitHub Secrets, Actions environment variables, PRs or prompts. A future authorized production deployment must retrieve scoped credentials at runtime from an external secrets manager, with key rotation and revocation runbooks, outside public CI.
- This bootstrap's GitHub Actions may use only the short-lived read-only checkout token required by GitHub; no workflow may reference product secrets, privileged `pull_request_target`, deploy tokens or production accounts. Limit `permissions: contents: read`; do not enable credential persistence after checkout. CI artifacts contain provenance/test metadata only, never arbitrary environment dumps or raw operational logs.
- Required prevention layers: project Git ignore rules, local opt-in Git pre-commit staging scan, full tracked-tree CI secret/path scan, stand-alone public-security status check, human review. Scanner catches known patterns only and must never be described as a guarantee against every possible leak. If sensitive material escapes, remove access, immediately rotate/revoke keys, investigate Git history/forks/artifacts and document the incident; deleting a commit alone cannot undo exposure.
- Existing HIVE upstream may generate a LOCAL `.env` in `D:\\Tools\\HIVE`; it is outside the Fairview repository, not supplied as a Fairview artifact, and must remain on the operator machine. Never mount local private HIVE data into GitHub CI.
- Release blocker: production launch is BLOCKED if repo PRIVATE visibility has not been authoritatively verified, or if security, runtime key management, independent HIGH_ASSURANCE review and recovery evidence are missing.
