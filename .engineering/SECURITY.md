# FairView security | financial HIGH_ASSURANCE

Never commit API keys, wallet seeds/private keys, passwords, PII, sensitive customer account data, any .env including examples, paid licensed raw ticks or real trade logs. A PUBLIC repo is permanently non-confidential even after eventual visibility changes. Every new privileged trading route requires separately approved threat model, lawful venue/strategy permissions, durable local intent plus authenticated external order/fill/position reconciliation, deterministic failure and rollback drills, independent Risk Kernel/kill and qualified high-assurance security review.

Source development uses a local Git checkout, Node22 and pinned GEF submodule only. No extra background context service, machine-wide database or Docker resource is required, and scripts must not modify data belonging to unrelated projects. The development bootstrap has no financial runtime, keys or broker signing features. HIGH/CRITICAL known findings block approval.

## Public development and production boundary (accepted D-008)
- Public source and unprivileged CI are allowed only for dummy development. Before financially funded deployment obtain actual PRIVATE-repository visibility receipt, independent risk/security acceptance, tested key rotation and least-privilege managed external secrets. Changing visibility does not remove earlier public Git history/forks.
- Never track FairView .env/.env.example, private keys, customer data, production logs or credentials, including in tests, GitHub Actions, issue/PR comments, screenshots or PDF prompts. Future production accounts retrieve secrets from an external managed store outside public CI and out of developer commits.
- GitHub Actions use only short-lived read-only checkout permissions, actions/checkout credential persistence disabled, no privileged pull_request_target or production deploy token. Upload metadata-only redacted Evidence Bundles, not environment dumps or secret-bearing logs.
- Layers: gitignore plus opt-in staged pre-commit scanner, full tracked-tree CI scanner, stand-alone public security check, real code review and secret rotation/revocation incident plan. Scanner is a fallible preventive check, not proof against every possible leak.
- No external indexing-service token, Docker volume or privileged local service is part of FairView's foundation. Product integration will be considered only when an independently adopted provider-specific source Work Order requires it.
- Reject live launch unless verifiably PRIVATE, named lawful venue/data rights, segregated account/position proof, financial fail-closed kill and unknown-order reconciliation, independent high-assurance review, safe rollback and operator authorization all pass.
