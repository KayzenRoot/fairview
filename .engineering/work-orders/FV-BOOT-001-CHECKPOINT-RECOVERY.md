# FV-BOOT-001 | Exact-HEAD checkpoint reconciliation (same Work Order)
Problem: a versioned checkpoint cannot contain its own final Git commit SHA without changing that SHA again. After PR #2/#4, versioned audit fields refer to historical pre-merge commits; the previous PDF's requirement to equate these to the current main HEAD caused a circular admission deadlock.
Scope: introduce a read-only Windows preflight that compares local HEAD == fetched origin/main == live GitHub main API ref; requires a completed successful GitHub main push workflow at the exact SHA with all four named jobs, and an **external**, owner-authored GitHub issue #1 attestation recorded after that run. Non-secret full-tree scan must pass. This admits LOCAL DEVELOPMENT GEF/HIVE installation attempts ONLY, not production deployment nor checkpoint independent promotion.
Authority: Source hierarchy, current checkpoint (historical records preserved), D-008 public-dev/no-secrets rule, FV-BOOT-001, PR #2/#4 exact-head CI and merge receipts. Source pack and CI remain canonical; no fake independent review or forced git cleanup.
Security: no secrets/config files in Fairview repo; no login token provided to unprivileged public CI or in PDFs. External local HIVE may preserve its machine-only .env. Public repo means API preflight can be unauthenticated; when switching PRIVATE later, replace the protocol in a separately audited Work Order.
Conditions: never auto-reset/rebase/checkout a divergent local HEAD (the user's screenshot displays a different prefix from verified remote main); if divergence or dirty tree, STOP with proof. If remote moves, all references/receipts must be reobtained for its new HEAD. No assumption that CI success is proof of Windows HIVE health, registry or semantic retrieval.
Implementation: scripts/local/verify-checkpoint.ps1; invoked as first state gate by scripts/local/setup-windows.ps1 -Mode Install. Windows CI parse and deterministic contract tests. All other live runtime and independent product review gates remain untouched.
Acceptance: exact-head source/security/Windows/GEF checks; no cyclic current-SHA-in-current-commit assertion; after merge, add issue #1 external receipt containing new current main SHA and CI run ID. Only then run local preflight, installing HIVE **if** all gates succeed.
STOP: status LOCAL_DEV_PRECHECK_ELIGIBLE is NOT a promoted checkpoint and NOT financial production. Installation requires separate measured local proof; issue #1 remains open; issue #3 protection/privacy tracked as before.
