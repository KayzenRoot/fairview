# FairView architecture | observed source versus planned financial runtime

FairView is a browser-operated, server-executed multi-market research platform with **future** independently authorized Forex, centralized-crypto and DEX trading. The approved development architecture is versioned Git Source Pack, accepted decisions/ADRs, narrow WOs/context locks, pinned GEF source-workspace Git submodule and dependency-aware Node 22 harness with exact-head CI/evidence. No auxiliary memory database, Docker stack, Python installation or semantic provider is necessary for the current source foundation.

**Observed merged SOURCE ONLY, not a live runtime:** bootstrap and three fictional-input-only pure Node kernels are ACTIVE in module-harness terms: `policy`, `clock` and `market-data`. Their real deterministic positive/negative tests exercise synthetically constructed policy grants, lossless invented clock domains and invented quote/sequence quality. None provides trusted real entitlement, OS clock calibration, authentic vendor data, real trade approval, durable financial history or independently certified release. Remaining 16 product modules are PLANNED.

**Future runtime boundaries (not adopted by source tests):** standalone authoritative Risk/Policy, measured provider clock uncertainty and lawful market data, separately evidenced durable Ledger and externally reconciled venue order/fill/position state; independently scoped Forex/CEX/DEX connectors; deterministic Replay/Research; bounded advisory AI and permissioned operator Web UI. Risk must DENY uncertain permissions, source age/clock, inventory and possible external fills. Browser/AI may never override risk or directly transmit orders/sign transactions.

PostgreSQL, Rust/Tokio, CCXT, Uniswap SDK, Next.js and observability stacks are candidate technologies; each requires its own accepted ADR/WO/licence/security review. The proposed FV-CP-0002 checkpoint remains unpromoted despite observed source merges. D-007/D-008 production gates remain open.
